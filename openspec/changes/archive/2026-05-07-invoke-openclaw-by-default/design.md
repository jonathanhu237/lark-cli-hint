## Context

`lark-cue` now has the Feishu knowledge loop working: it wraps a command, requires an LLM planner, retrieves Feishu evidence when the failure appears internal-knowledge related, and renders a cited card with an action plan. That is still incomplete for the OpenClaw contest story because the knowledge remains terminal guidance rather than execution context for an agent runtime.

The user decision for this change is explicit: OpenClaw should be the default post-card execution path. Users can opt out with a flag, but the normal product experience should be `lark-cue` enriching a failed workflow with Feishu evidence and then handing the task to OpenClaw to inspect and repair the local workspace.

## Goals / Non-Goals

**Goals:**
- Make `lark-cue run -- <command>` require OpenClaw preflight by default, after the existing LLM preflight and before executing the wrapped command.
- Add `--no-openclaw` as the explicit card-only opt-out.
- Generate a stable OpenClaw task message with command failure context, planner output, Feishu evidence, knowledge card fields, action plan, working directory, safety constraints, and verification instructions.
- Invoke `openclaw agent --local --agent main --timeout 900 --message <task>` after rendering the knowledge card when planner retrieval is true.
- Stream OpenClaw stdout/stderr to `lark-cue` stderr and preserve the wrapped command exit code.
- Keep tests deterministic by injecting a fake OpenClaw runner rather than requiring OpenClaw in default tests.

**Non-Goals:**
- Do not support `--to`, `--session-id`, multiple agents, or custom OpenClaw selectors in this MVP.
- Do not use OpenClaw for planner `should_retrieve=false` failures.
- Do not replace Feishu retrieval with OpenClaw web search or local search.
- Do not let OpenClaw send Feishu pushes; Feishu push sending remains explicit.
- Do not make OpenClaw success turn the original failed command into exit code `0`.

## Decisions

### Default OpenClaw, explicit opt-out

Default `lark-cue run` will enable OpenClaw handoff. A new `--no-openclaw` flag disables both OpenClaw preflight and post-card invocation.

Rationale: the product should be an OpenClaw-enhanced enterprise troubleshooting assistant, not only a card generator. Making OpenClaw opt-in would undercut the selected direction and contest demo.

Alternative considered: add `--openclaw` as opt-in. Rejected because the user wants OpenClaw to be the main path.

### Preflight before wrapped command execution

Default mode will check OpenClaw before running the wrapped command. Missing or failing OpenClaw preflight returns CLI/config exit code `2` and does not execute the wrapped command.

Preflight should be fast and side-effect-minimal:
- Resolve the configured binary, default `openclaw`.
- Run `openclaw agent --help`.
- Do not do a real agent dry-run in preflight.

Rationale: if OpenClaw is the default handoff, users should know before a potentially side-effectful wrapped command runs that the main repair path cannot work.

Alternative considered: wait until after card generation to discover OpenClaw is unavailable. Rejected because it creates a late failure after command execution and Feishu retrieval.

### Use `main` local agent only

Invocation command:

```sh
openclaw agent --local --agent main --timeout 900 --message "<task>"
```

Rationale: OpenClaw has a reserved/default `main` agent, and the MVP does not need selector complexity. The user explicitly asked not to keep exploring other targets once `main` was acceptable.

Alternative considered: require explicit user configuration of agent/session target. Rejected as unnecessary setup friction for the MVP.

### Go template for task message

The OpenClaw task message will be generated by deterministic Go formatting, not by another LLM call.

The template will include:
- Goal and high-level instruction.
- Current working directory.
- Failed command and exit code.
- Captured terminal output excerpt.
- Planner scenario, reason, and queries.
- Knowledge card likely cause, caveat, confidence, and action plan.
- Feishu citations and snippets.
- Safety constraints: ask before deleting data, changing production configuration, rotating secrets, sending messages, or committing code.
- Execution constraints: inspect local state first, adapt to findings, and rerun the failed command or an equivalent verification.

Rationale: the intelligence comes from planner/card/evidence. The handoff envelope should be stable, complete, and testable so safety constraints cannot be accidentally omitted.

Alternative considered: ask the LLM to generate the OpenClaw prompt. Rejected to avoid another model call and avoid losing required constraints.

### Output and exit semantics

OpenClaw stdout and stderr will both stream to `lark-cue` stderr. The wrapped command's stdout remains untouched.

If OpenClaw invocation fails or times out after the wrapped command has failed, `lark-cue` prints a diagnostic and returns the original wrapped command exit code.

Rationale: `lark-cue` is still a command wrapper. OpenClaw is the repair attempt, not the wrapped command result.

### Evaluation

Cue evaluation records should capture OpenClaw status without changing the existing planner/cue split. Fields should be simple and JSONL-friendly:
- attempted
- skipped reason when not attempted
- exit code or timeout/error when attempted
- latency milliseconds

Rationale: the demo validation report should show that the OpenClaw handoff happened and whether it completed, while keeping default tests deterministic.

## Risks / Trade-offs

- [Risk] OpenClaw CLI flags or behavior drift. -> Mitigation: isolate shelling out behind an adapter and keep the command shape in tests.
- [Risk] OpenClaw unavailable blocks default runs. -> Mitigation: the error tells users to install/configure OpenClaw or run `--no-openclaw`.
- [Risk] OpenClaw output could pollute stdout. -> Mitigation: always route OpenClaw output to stderr.
- [Risk] Long-running agent turns make `lark-cue run` feel stuck. -> Mitigation: use a default timeout of 900 seconds and print an invocation status before running.
- [Risk] Task prompt omits critical evidence. -> Mitigation: build the task from the same card/citation/evidence structures used for terminal output and cover it with tests.
- [Risk] Evaluation fields grow too much. -> Mitigation: store compact OpenClaw result metadata, not full OpenClaw transcripts.

## Migration Plan

1. Add config defaults for the OpenClaw binary and timeout, keep local `main` as the fixed MVP target, and document `--no-openclaw`.
2. Add OpenClaw adapter and task builder behind interfaces for tests.
3. Wire preflight before wrapped command execution in default mode.
4. Wire post-card invocation only for planner retrieval path.
5. Extend evaluation record/report output.
6. Update README/demo docs to tell users how to install/configure OpenClaw and verify `openclaw agent --local --agent main`.

Rollback is straightforward: run with `--no-openclaw` or revert the default OpenClaw preflight/invocation wiring.

## Open Questions

- None for MVP. Future changes can add custom agents, session targets, direct API/Gateway invocation, or richer OpenClaw execution scoring if the default CLI integration proves useful.
